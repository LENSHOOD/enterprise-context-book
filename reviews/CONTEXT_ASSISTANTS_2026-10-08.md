# 平台内部智能辅助实现与自审（rc.25）

本记录针对书稿和 Northstar 的新增能力，不是独立同行评审，也不是生产模型效果报告。

## 设计与范围

- 保留企业资源、企业上下文平台和任务上下文三部分逻辑架构。内部智能体参与这些工作，不新增第四类架构对象。
- C8 从原始说明材料开始，提出类型、能力问题和服务说明关系；经结构校验与人工审核后，重建模型、检索、图和模板 Wiki。原文修订、候选和发布历史保存在实验空间。
- C9 先提出任务理解并确认，再逐步调用角色允许的读取工具，交付材料、解释草案和缺口。任务理解确认与经营指标契约确认分开；内部取证完成不代表业务任务完成。
- 两个工作流程共享模型接口、校验和 SQLite 保存。fixture 是手写脚本；http 是真实模型接口，错误不会自动降级成脚本。

## 自审发现与修复

1. 模型响应的信封、候选或 usage 类型错误可能绕过异常转换。补充统一模型错误处理及协议回归测试。
2. 新资源发布改变 Manifest，发布记录应以发布后的版本判断是否陈旧，已修正并增加断言。
3. 新鲜的当前队列状态不能证明之前取得的读数仍然有效。交付时比较当次材料与当前有效观察，不一致或过期即标为缺口；历史读取仍保留。
4. 任务确认界面原先折叠了目标和范围。现在直接显示目标、范围、完成条件及问题；新增字段补上中文名称。
5. 网络读写超时不是调用总截止时间。书稿和界面改为区分45秒网络超时、60秒页面等待以及尚未实现的服务端总截止时间；提示恢复记录后再考虑重试。
6. 通读新增章节与旧说明，修正“没有模型”“图边全部人工编写”等过时描述，同时保留基础流程、模板 Wiki 和离线语义代理的真实边界。

## 未验证与实现边界

本次环境没有配置可调用的真实模型，未验证任何实际模型的语义质量、选路效果、延迟或费用。不能把协议服务器、测试替身或手写脚本当成真实模型调用记录。第13章补充两类成绩单：程序边界测试与真实模型效果评测。

教学角色可切换，不是生产身份认证。C8 的维护者兼审核人；新资源限于说明材料和“材料描述服务”的关系，不包含任意本体迁移、实体合并、外部原文写回或模型生成 Wiki 摘要。C9 按点击推进，不含后台自主调度；模型解释未做逐句自动核验。服务未实现生产级并发限流、费用上限和持久模型活动；并发冲突或中途重启可能重复计费。

历史来源与记录保留，不等于提供完整的历史资源查询。已发布版本和网站状态以对应提交与 GitHub Actions 为准。
