# 后续案例与前十三章同步复核（rc.20）

## 范围与结论

以 rc.19 的前十三章为基线，审阅第十四至十八章、Linux 番外、W2 专页、案例 README 与规格。重点核对四类问题、资源—平台—任务上下文、六方面企业内容、建模与取证方法，以及工程能力是否真的实现。

需要更新的主要是教学衔接与能力表述。Northstar 已有领域和经营两套教学数据，W2 已有嵌入式主机模型，Linux 已有固定提交索引；本轮不增加新的执行能力。代码资产仅修正 C7 订单服务对象的说明，明确跨切片身份对接尚未实现。

## 发现与处置

| 问题 | 处置 |
|---|---|
| 三条工作线被叫作三类任务，与第一章四类问题混用 | 第十四章改为工作线，说明认知、决策、执行的组合，连接 W2 创造任务 |
| 后续案例缺少与三个逻辑部分及前文方法的对应 | 增加资源、平台、任务上下文的具体产物表及方法—练习—扩展导航 |
| 图、Wiki、记忆和架构声明被统称为同源派生视图 | 第十四、十六、十七章说明各自来源，修正数据流图 |
| C3 的三条领域能力问题与 C7 经营问题混入同一验证叙述 | 分开模型输入、实例连通校验与经营快照校验；测试命令加入 strategy 套件 |
| 第八章的企业整体建模在案例中展开不足 | 第十六章逐项对应六方面企业内容，追踪目标、指标、数据来源、能力和责任；用缺失漏斗快照讲清数据缺口 |
| 人工 `resolved` 标签被误读为程序解析证明 | 就近说明只校验关系契约及证据字段，不验证引用真实性或执行跨仓解析 |
| `abc123` 与知识对象 `observed_at` 含义不够明确 | 说明虚构版本坐标，以及平台记录时间与实时采样时间的差别 |
| 任务包的条件、覆盖与记忆能力被泛化 | 对应第三章任务结构；区分 operational 与 strategic 的输入、输出和覆盖报告；说明进程内事件与空战略记忆 |
| 动作 `resolved` 被说成真实业务完成 | 说明同进程模拟状态、有限观察规则，以及 842→742 不代表事故解决或退款到账 |
| 观察失败与拒绝执行后的恢复流程表述超出实现 | 区分保持 verifying 与转入 needs_human；说明同任务重新诊断入口未实现 |
| 战略金额无单位、时钟与运行案例易混 | 补千美元单位、同比较差异及目标差距；标注独立的 2027-01-02 虚构快照 |
| W2 与后续实践脱节 | 第十七章连接需求、设计、固件约定、主机代码、验证缺口和评审边界，增加双向导航 |
| Linux 的边界策略、机制视图及名称解析易被当成已实现语义 | 区分显式 scope 与目标策略、正则启发式与编译关系；注明两次历史运行日期 |
| C7 的 service-order-ledger 声称与运行切片共享身份，实际无同 ID 对象 | 修正第十六章与 fixture note，保留为待对接身份 |

独立审阅者先核对实现与旧书稿，运行 64 项测试并用内存反例检查验证边界；修订后再检查完整差异、C7 新列关系与章节链接。最后一项共享身份表述在第二遍审阅中发现并修正。没有把关系表完整性检查、真实源码解析或动作恢复等尚未实现的功能补写成既成能力。
