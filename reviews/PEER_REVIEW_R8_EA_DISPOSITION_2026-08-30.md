# R8 企业架构同行评审处置记录（2026-08-30）

处置对象：`PEER_REVIEW_R8_EA_2026-08-30.md`。R8 第一部分确认 R7 已闭环；第二部分提出 E-1 至 E-6。发布裁决仍以 `run_manifest.json` 为准，当前维持 `not-cleared`。

## 总体判断

R8 对覆盖缺口的核心判断成立：R7 版本没有点名企业架构传统，没有把能力地图、流程模型和架构视图作为一等来源，也没有业务流程层级或架构声明与运行证据的一致性场景。将这些内容分布到既有章节，比新增一章更符合本书“消费 EA 资产而不讲授完整 EA 方法论”的边界。

有三处建议需要收紧后采纳。

第一，“本书内容与 EA 同源”只能证明概念重叠，不能证明直接思想来源；正文改为说明二者的对应关系，不声称既有六视图或生命周期直接源自某一框架。第二，“EA 描述设计中的企业，企业上下文捕捉运行中的企业”过于二分。现代 EA 也包含反馈、治理和 fitness function，因此正文改为：EA 提供目标状态与当前声明等规范性资产，企业上下文把这些声明编译为智能体可用证据，并与代码、配置和运行观察持续比较。第三，未找到仍可公开访问的 Thoughtworks 官方 MEAF V4 页面；按用户提供的站点引用时明确标注它是个人学习镜像、版权归 Thoughtworks，同时补充 Thoughtworks 当前官方 Enterprise Architecture Playbook，不把二者混称为同一文档。

## 独立复核后的修正

初版处置完成后，又对 R8 差异执行了一轮独立只读复核，并采纳三项契约级发现。第一，`domain-model.json` 的来源映射现已明确说明 API 注册表产生规范 API 实体、代码索引产生解析出的 `CALLS` 关系，而企业架构库和运行追踪均可产生各自证据范围内的 `API` 与 `CALLS`，避免新增数据游离于机器可读模型之外。第二，`architecture-claims.json` 用 `from_ids` 明确限定退款服务，比较器同时执行关系类型、起点、可选终点和 ACL 过滤；回归测试会注入一条对开发者可见但不在范围内的 `CALLS` 边，确认它不会污染结果。第三，E-4 的处置文字已收紧：第 3、14 章负责来源示例和实施任务，只有第 11 章明确给出来源契约状态枚举。

- Zachman 论文的题名、期刊、卷期和 1987 年出版信息通过 DOI `10.1147/sj.263.0276` 核验。
