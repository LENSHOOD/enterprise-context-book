# Northstar 共用流程与第四部分自审

日期：2026-10-09。目标版本：v1.0.0-rc.26。本文是本轮实现者自审与执行记录，不是独立模型评审。

## 审阅结论与修订

旧版第14章混合了案例能力、Web 操作及实验空间的内部机制；资源建设和调查助手单独出现较晚，难以看出资料整理本来就需要判断。代码中，经营模式也确实从 `context()` 提前返回另一套包装逻辑，仅共用外部入口。以上问题需要正文与实现一起调整。

| 问题 | 本轮处理 | 核对依据 |
|---|---|---|
| 示例核心与实验载体混杂 | 第14章围绕资源建设、任务调查、职责及技术讲解；数据库恢复与并发移至工作台折叠说明 | 第14—17章、`book/lab.md`、教程源码清单 |
| 任务流转难以理解 | 14.2.3 只讲任务经过系统的过程，下一节再对应代码；14.3 以三类任务对照共同阶段 | 正文、两张 Mermaid 图 |
| 助手像最后增加的功能 | 从来源理解开始区分人或助手的判断、确定性处理和有权确认；说明初始文件是人工整理结果，C8/C9 是练习编号 | 第14章总图与分工表，第15、16、17章衔接 |
| 经营任务使用独立包装路径 | 提取 `ContextFlow.plan/read/assemble/run`，三类任务使用同一执行循环与组装器；C9 复用读取入口 | `context_flow.py`、`northstar.py`、`intelligence.py` |
| 操作界面不容易看出共同流程 | 上下文结果展示查询工具、目的与参数；源码面板以核心函数为入口 | C5/C7 本地实际交互及页面源码选择项 |

`strategy.py` 继续负责指标专用契约、企业资料校验和计算。共同流程不要求所有资料统一成文本，也不要求每个任务都调用所有工具。固定计划由调用方明确选择，尚不是通用模型规划器；C9 另保存逐步调查材料和解释草案，复用读取工具但不宣称业务任务已完成。

- `npm run docs:build` 通过，包括构建时样例执行、AST源码提取和内部链接检查。保留既有的大块资源体积提示，没有构建错误。

助手演示使用手写 fixture；本轮没有真实模型服务配置，不能据此声称验证了真实模型的建模或规划质量。SQLite、HTTP和模型等待实现保留，只改变正文的讲解位置与源码阅读入口。历史评审材料和用户的未跟踪文件未纳入本轮提交。
