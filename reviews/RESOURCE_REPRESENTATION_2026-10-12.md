# 企业资源的定义、记录与视图复核

日期：2026-10-12

对应版本：v1.0.0-rc.29

## 修订范围

本次调整第三章与第八章的资源组织说明，并同步目录和发布元数据。Northstar、Linux 和 W2 的案例代码及数据没有改变。

第三章原来的表达方法表把本体、流程、指标定义、图谱与阅读视图并列，容易让读者误以为它们是互斥的资源类别。修订后依次说明企业内容范围、对象与业务约定、具体记录、查询与阅读方式，以及来源和使用条件；用预算与销售指标解释这些方面如何共同作用于同一份材料。

## 主要核对结果

| 复核问题 | 修订后的说明 |
|---|---|
| 流程是否必须独立于领域模型 | 事件、状态、规则和动作可以在同一业务模型中表达流程；顺序、分支、等待、并行汇合与失败条件需要充分说明，实际执行仍依赖运行机制 |
| 指标定义与数值是否混淆 | 定义明确含义、口径、单位、粒度、维度与来源；目标、预测和实际值分别保存期间、范围、版本及依据 |
| 本体与知识图谱是否被绝对分开 | 图谱可以组织定义与实例声明，OWL 本体也可以包含个体并以 RDF 图表示；面向用途选出的关系展示才是具体视图 |
| 企业业务数据是否有位置 | 补充订单、会计分录、预算、库存、人员设备台账和工程产物；说明原系统保留明细、平台经受控入口按需读取的方式 |
| 视图是否被当作事实证明 | 区分计划、要求、实现、观察与推断；图、报表和 Wiki 保留原材料的性质与证据，不因展示方式改变而提高可信程度 |
| Wiki 与 Runbook 是否一律派生 | 正式 Wiki 页面可以是原始来源；平台生成的说明是派生视图。Runbook 正文保留为来源，步骤和服务引用可用于其他表示 |
| 六方面企业内容是否覆盖 | 第3.2.4节逐项列出可接入资源及任务使用方式，连接商业模式、战略、能力流程、组织资源、应用技术和运行历史 |
| 教学代码是否被夸大 | 明确 Northstar 经营数据是预聚合快照，没有真实数仓查询与预测引擎；流程查询也不等于通用流程执行引擎 |

第八章新增说明参照 W3C OWL 2、RDF 1.1 和 dbt 语义模型官方材料，链接留在相应正文。第三章总图与小结、方法导航和详细目录采用一致的表述。
