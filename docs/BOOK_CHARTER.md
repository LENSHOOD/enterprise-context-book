# 《企业上下文：从知识库到智能体认知基础设施》写作宪章

> 文档类别：项目治理与写作边界。

## 1. 出版定位

本书是一部个人署名、公开发布、证据驱动的方法论与工程实践著作。它不宣传特定产品，也不以作者经历作为论证基础。它通过历史沿革、技术机制、架构判断和可复现实战，建立“企业上下文”这一统一认知框架。

## 2. 写作目的

让企业 AI 平台负责人、架构师和高级工程师能够：

1. 区分知识、记忆、实时状态、权限、工具和任务上下文；
2. 理解 RAG、Wiki、Graph、Memory、代码知识等技术的职责与边界；
3. 识别一个企业知识库方案的能力缺口和风险；
4. 设计从证据检索走向可治理、可行动企业上下文平台的建设路径；
5. 与产品、业务和工程团队使用同一套术语讨论架构与验收。

## 3. 核心论点

> 企业上下文是连接企业真实世界与智能体的认知基础设施。

知识库只承载其中相对稳定、可复用的事实、规则、解释和关系。完整企业上下文还包含 Agent 记忆、实时业务状态、身份权限、工具能力和当前任务环境。

全书捍卫以下判断：

- 知识库不等于向量数据库，RAG 也不等于完整知识体系；
- RAG、Wiki、图谱和记忆是互补知识形态，不是互斥方案；
- 企业知识系统的核心问题正从存储转向上下文选择、证据验证和治理；
- 原始来源是事实基础，摘要、图和向量是可重建的派生知识；
- 权限、版本、时间、来源与评测必须进入知识生命周期，而非事后附加；
- “知道”与“能做”必须分权治理，知识访问不自动授予工具执行权；
- 领域原生结构应被保留，代码、Schema、业务对象不能全部压平成文本块。

## 4. 读者与前置知识

核心读者是企业 AI 平台负责人、架构师和高级工程师；兼顾产品负责人和技术管理者。默认读者了解 LLM 和常见软件系统概念，但不要求掌握 RAG、知识图谱、Agent 记忆或代码智能。

## 5. 内容边界

正文覆盖历史、概念体系、知识生命周期、企业架构资产接入、技术架构、治理、评测、企业实践和两个实战案例。企业架构在本书中作为知识来源与建模传统被消费，不展开完整 EA 方法论。模型训练、通用数据库教程和产品排行榜不作为主线。易过时的安装命令和完整代码放入配套仓库，正文保留稳定原理、关键片段与实验结果。

## 6. 写作方式

采用“问题驱动的技术叙事”。典型章节结构为：问题与失败场景、历史与概念、技术机制、架构取舍、案例推进、常见误区、章节结论、延伸阅读。

写作要求：

- 清晰、克制、少用论文腔和宣传语；
- 外部事实、论文结论和项目能力就近引用；
- 项目自报数据明确标注来源，不外推为企业效果；
- 事实、作者综合判断和未来推测显式区分；
- 图表服务于关系理解，代码服务于机制解释；
- 同一术语在全书保持一致定义。

## 7. 实战案例

主案例是虚构软件企业的订单研发与运维上下文系统，完整覆盖来源、解析、索引、Wiki、图、记忆、混合检索、权限、引用、评测和 Agent 接口。

进阶案例是 Linux 内核子系统知识库，第一版优先选择 eBPF 或调度器，目标是形成作者能够长期使用的源码学习与研究工具，并说明如何从子系统扩展到整个内核。

## 8. 技术与授权

正文保持厂商中立；论述中的目标参考栈包括 Python、PostgreSQL/pgvector、轻量图、Tree-sitter、SCIP、Markdown、MCP/REST、Docker Compose、GitHub Actions 和 VitePress，组件必须有清晰替换边界。本仓库交付的是最小纵向切片：以 Python 标准库验证对象、ACL、版本化引用、BM25、离线语义代理、确定性图遍历、模板 Wiki 和受控动作契约；PostgreSQL/pgvector、Tree-sitter、SCIP 与 MCP/REST 属于生产化路线，不包含在 Northstar 可运行代码中。

书籍正文采用 CC BY-NC-SA 4.0，示例代码采用 Apache-2.0。Linux 源码不复制进仓库，案例固定上游版本并由读者自行获取。

## 9. AI 使用声明

作者为唯一署名者和最终责任人。AI 用于资料整理、检索、草稿、引用检查和代码辅助；所有事实、观点和发布内容由作者最终确认。无可验证来源的外部事实不进入定稿。

## 10. 完成标准

- 定稿目标为中文 8–12 万字、14–18 章；发布候选按脚本统计并明确标注是否达标；
- 两个案例具备可复现产物，主案例可从空环境按步骤运行；
- 外部事实和项目能力有可访问引用；
- 每章完成事实、技术和可读性审阅；
- 内部链接、引用、图表、代码和命令通过自动检查；
- VitePress 网站通过 GitHub Pages 发布；
- 仓库包含许可证、引用说明、贡献指南、版本记录与研究方法；
- 发布明确的 v1.0。

## 11. 审阅门

1. 写作宪章、详细目录、核心论点与案例规格；
2. 样章与案例原型；
3. 完整初稿；
4. v1.0 发布候选。

审阅门之间自主推进；只有会改变核心主张、案例范围或公开边界的问题才单独请求决策。
