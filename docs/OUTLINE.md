# 详细目录 v1.0.0-rc.30

> 文档类别：书稿结构与章节范围。

本目录反映当前 18 章、番外与附录 A—G 的实际结构；`reviews/run_manifest.json` 是历史审计记录，当前版本状态以仓库提交与 GitHub Actions 为准。

## 第一部 为什么需要企业上下文

### 第 1 章 智能体为什么不懂企业

用退款处置、销售分析和 W2 软硬件协同设计引出企业上下文，按主要交付结果定义认知、决策、创造和执行四类问题，再以资源、平台和任务上下文三个整体建立认识，介绍从战略到运行的企业内容范围；内部组成与运行过程放到第三章展开。

### 第 2 章 从知识管理到企业上下文

回顾文档管理、数据库与搜索、专家系统、EA、语义建模、向量、RAG 和 Agent 的发展，将各自贡献映射到第一章总图，不把演进写成线性替代。

### 第 3 章 企业上下文怎样组织起来

完整展开企业上下文资源、任务上下文和平台，以建设、调查和维护三条流程连接它们。说明目标与理由、实现和观察怎样保留，结构化关系怎样直接支持查询，本轮上下文包怎样贡献于任务上下文。用销售分析与W2设计展示形成解释与形成新成果，方法和工程导航指向第二、三部分。

## 第二部 核心方法与技术选择

### 第 4 章 资料准备：从来源到可引用的证据

从任务盘点客户、战略、组织、应用与运行资料，恢复文档与代码结构，构造可引用单元并保留身份、坐标和使用条件；比较解析器、Docling/Unstructured、代码索引器与编排框架，说明准备结果怎样进入 RAG。

### 第 5 章 检索：选择通道，再组合证据

解释词法、向量与结构化查询，区分表示模型、精确/近似索引、融合与重排；区分逻辑计划与执行计划、约束下的成本选择与质量取舍，讲结构路径和证据预算，再比较搜索服务、向量后端、模型工具链与指标查询技术。

### 第 6 章 关系与层级：沿结构查找证据

区分来源层级、业务关系与生成结构，讲有界下钻、关系证据及代码导航；用 W2 演示从工程需求追查企业目标与实际效果，再比较父子块、PageIndex、RAPTOR、GraphRAG/LightRAG 和 Tree-sitter/SCIP/LSP 的适用范围与验证方法。

### 第 7 章 Wiki：把反复查资料的工作提前做好

按来源、模板、声明、检查、发布和增量维护讲解编译式 Wiki；覆盖企业概览、能力、目标与系统等阅读视图，说明人工修订与来源冲突，再比较模板实现、CodeWiki 与 OpenWiki 等专项技术及其边界。

### 第 8 章 知识建模与本体：把业务说法变成可检查的约定

以任务与证据为起点，借鉴企业架构方法建立商业模式、目标、能力与价值流、组织、应用数据及运行的联系；用 W2 连接企业目标和工程要求，再展开领域对象、身份、状态、规则与动作。说明流程怎样融入业务模型，指标定义怎样关联目标、预测与实际值，图谱怎样组织定义及实例；映射来源并以实例和反例验证。最后选择词表、Schema、关系表、图、指标语义层、RDF/OWL/SHACL 等表达与工具，交付可维护的企业和领域模型。

### 第 9 章 任务上下文与记忆：让材料随工作推进

讲清任务条件、取材路径、根据缺口改计划、停止条件和证据预算，以条件、发现、依据及缺口组织调查交付；内部助手可以分析，外部使用方继续负责业务目标和行动。再讲携包续问、恢复及记忆管理，比较持久任务状态、LangGraph、Mem0、Graphiti等不同技术职责。

## 第三部 平台工程与运行保障

### 第 10 章 把零散知识能力装成一个平台

给出模块、适配器和预索引/直接查询两条路径，说明候选计划、来源统计、估计与实际预算、执行反馈；完整说明 Context API 请求、响应、缺口决策与异步恢复契约，补齐持久编排、缓存隔离、故障和背压，按职责比较框架与协议。

### 第 11 章 同一份知识，怎样避免认错版本和时间

落实统一 ID、版本、双时间、权威性、血缘、增量更新、删除和快照发布；补充模型与实例共同验证、存储及校验工具的实现取舍。

### 第 12 章 Agent 能看什么、记什么、改什么

从读取、派生知识与记忆安全进入完整受控动作工程：状态机、批准绑定、TTL、并发与幂等、回执、独立验证、部分成功、对账、补偿和事件级联；比较 IAM、OPA/OpenFGA、Temporal 等实现选项。

### 第 13 章 怎么知道知识系统真的有用

将方法与契约转成金标、分层指标、消融、回归、影子与金丝雀验证；说明追踪、SLO、成本和容量，并比较确定性测试、Ragas/DeepEval 与 OpenTelemetry 的职责。

## 贯穿示例：W2 软硬件协同研发

在第一部分引出协同设计目标，第二部分把企业能力与责任连接到器件、驱动、协议、代码和工程要求，第三部分承接草案工作空间、版本、权限与验收。`book/cases/hardware-w2.md` 展开硬件预算、嵌入式软件模块、记录与确认、断网及重启行为；`examples/hardware-design/` 提供企业背景、软件契约、绑定输入的设计草案、预算检查和Python主机行为测试。企业关系由读者人工核对；未提供MCU驱动、可刷写固件或板级实测。

## 第四部 从零构建一个企业上下文系统

### 第 14 章 先看见案例，再开始构建

先介绍企业与三条工作线，再以资源建设和任务调查两条流程展开资源、平台与任务上下文。从起点区分人或助手的判断、程序处理及有权角色确认，说明三类任务如何共用计划、读取和组装；给出核心模块、资源清单、阅读路线和验收点，实验空间技术移至工作台说明。

### 第 15 章 从来源到可信检索

将资料准备、检索与版本权限契约应用到五份来源、对象编译器和查询函数；在设计讲解旁嵌入真实源码、C0-C2 参数实验和结果视图，保留 CLI 重建入口。

### 第 16 章 让系统按企业的含义连接知识

按“问题—模型—共同编译—使用视图—变化与交接”递进。从事件模型扩展到退款能力、流程与部署，再把经营快照纳入统一资源流程；C8 展示候选审核。四张图从校验后的实际资源生成，分别展示退款业务、技术运行、经营结构及观察关联。C4 从业务入口查到当前观察和手册，逐步呈现所用对象与引用，并保留关系导航、Wiki 和架构对照。解释来源专门校验与共同发布的分工，最后用政策更新及原文修订检查查询、模型和视图的一致性。

### 第 17 章 让 Agent 安全地把事情做完

沿请求、查询、核验、交付、续问和业务接续展开；固定路线与C9共用读取、组装及发现引用契约。C5-plan比较同一证据要求下的成本估计和实际用量；携引用续问重查权限、版本与时效。随后保存业务进展，分别讲解分析复核与退款动作，保留W2创造任务的对应关系。

## 第五部 真实世界压力测试

### 第 18 章 动手构建一个 Linux eBPF 知识库

固定上游版本，以 eBPF 建立正则符号候选关系、文件级 Wiki、BM25 查询和可验证源码引用；明确机制建模、Tree-sitter/SCIP/BTF/向量检索属于后续精度路线，分析宏、条件编译、大仓增量和扩展到全内核的挑战。
