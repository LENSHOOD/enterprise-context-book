# 详细目录 v1.0.0-rc.16

> 文档类别：书稿结构与章节范围。

本目录反映当前 18 章、番外与附录 A—G 的实际结构；`reviews/run_manifest.json` 是历史审计记录，当前版本状态以仓库提交与 GitHub Actions 为准。

## 第一部 为什么需要企业上下文

### 第 1 章 智能体为什么不懂企业

用退款处置、销售分析和 W2 硬件设计引出企业上下文，按主要交付结果定义认知、决策、创造和执行四类问题，再以资源、平台和任务上下文三个整体建立认识，介绍从战略到运行的企业内容范围；内部组成与运行过程放到第三章展开。

### 第 2 章 从知识管理到企业上下文

回顾文档管理、数据库与搜索、专家系统、EA、语义建模、向量、RAG 和 Agent 的发展，将各自贡献映射到第一章总图，不把演进写成线性替代。

### 第 3 章 企业上下文怎样组织起来

完整展开企业上下文资源、任务上下文和平台：资源的内容与材料组织，任务条件、所选依据及工作边界，平台的维护、语义治理和构造职责；用销售分析和 W2 设计分别展示形成解释与形成新成果，方法和工程导航全部指向第二、三部分。

## 第二部 核心方法与技术选择

### 第 4 章 资料准备：从来源到可引用的证据

从任务盘点来源，恢复文档与代码结构，构造可引用单元并保留身份、坐标和使用条件；比较解析器、Docling/Unstructured、代码索引器与编排框架，说明准备结果怎样进入 RAG。

### 第 5 章 检索：选择通道，再组合证据

解释词法、向量与结构化查询，区分表示模型、精确/近似索引、融合与重排；讲查询规划、结构路径和证据预算，再比较搜索服务、向量后端、模型工具链与指标查询技术。

### 第 6 章 关系与层级：沿结构查找证据

区分来源层级、业务关系与生成结构，讲有界下钻、关系证据及代码导航；比较父子块、PageIndex、RAPTOR、GraphRAG/LightRAG 和 Tree-sitter/SCIP/LSP 的适用范围与验证方法。

### 第 7 章 Wiki：把反复查资料的工作提前做好

按来源、模板、声明、检查、发布和增量维护讲解编译式 Wiki；说明人工修订与来源冲突，再比较模板实现、CodeWiki 与 OpenWiki 等专项技术及其边界。

### 第 8 章 知识建模与本体：把业务说法变成可检查的约定

以任务与证据为起点，依次确定对象、属性、关系、身份、状态、事件、规则和动作契约，映射来源并以实例及反例验证；最后选择词表、JSON Schema、关系表、属性图、RDF/OWL/SHACL 等表达与工具，形成可持续维护的交付成果。

### 第 9 章 任务上下文与记忆：让材料随工作推进

讲清任务条件、取材路径、上下文组成、证据预算、多轮刷新与恢复，再讨论记忆的写入、检索、压缩、纠错和遗忘；比较持久任务状态、LangGraph、Mem0、Graphiti 等不同技术职责。

## 第三部 平台工程与运行保障

### 第 10 章 把零散知识能力装成一个平台

给出模块、适配器和预索引/直接查询两条路径，完整说明 Context API 请求、响应、缺口决策与异步恢复契约，补齐持久编排、缓存隔离、故障和背压；按职责比较框架与协议。

### 第 11 章 同一份知识，怎样避免认错版本和时间

落实统一 ID、版本、双时间、权威性、血缘、增量更新、删除和快照发布；补充模型与实例共同验证、存储及校验工具的实现取舍。

### 第 12 章 Agent 能看什么、记什么、改什么

从读取、派生知识与记忆安全进入完整受控动作工程：状态机、批准绑定、TTL、并发与幂等、回执、独立验证、部分成功、对账、补偿和事件级联；比较 IAM、OPA/OpenFGA、Temporal 等实现选项。

### 第 13 章 怎么知道知识系统真的有用

将方法与契约转成金标、分层指标、消融、回归、影子与金丝雀验证；说明追踪、SLO、成本和容量，并比较确定性测试、Ragas/DeepEval 与 OpenTelemetry 的职责。

## 贯穿示例：W2 硬件创造

在第一部分引出设计目标，第二部分说明来源、检索、结构、知识视图、建模和设计任务上下文，第三部分承接草案工作空间、版本、权限与验收。`book/cases/hardware-w2.md` 集中保存设计草案和追踪表；`examples/hardware-design/` 提供教学输入、结构化草案与可运行的功耗/材料预算及引用检查。没有真实器件选型、物理测试或生产放行声明。

## 第四部 从零构建一个企业上下文系统

### 第 14 章 成品导览与构建路线

先展示 Northstar 的战略分析、影响分析与退款处置成品，说明企业上下文内容体系与当前任务条件，区分目标企业、教学 fixture 和生产替换路线，再给出 C0-C7 的构建顺序和验收点。

### 第 15 章 从来源到可信检索

将资料准备、检索与版本权限契约应用到 Northstar 的五份来源、对象编译器和查询函数；解释 C0-C2 的实现选择，再运行命令与失败实验验证。

### 第 16 章 让系统按企业的含义连接知识

将建模方法落实为四类人工输入、模型编译和连通实例报告，再解释 C3-C4 的关系查询、Wiki、记忆及架构对照，扩展到 C7 战略快照；设计说明围绕实际文件、函数和验收结果展开。

### 第 17 章 让 Agent 安全地把事情做完

将第 9、10、12 章的上下文与行动契约落实为 C5-C7 的本地方法、包字段、角色交接、状态转移与回归测试；解释教学实现的选择和生产替换边界。

## 第五部 真实世界压力测试

### 第 18 章 动手构建一个 Linux eBPF 知识库

固定上游版本，以 eBPF 建立 syntax-only 源码结构、符号候选关系、层级 Wiki、BM25 查询和可验证源码引用；明确 Tree-sitter/SCIP/BTF/向量检索属于后续精度路线，分析宏、条件编译、大仓增量和扩展到全内核的挑战。
