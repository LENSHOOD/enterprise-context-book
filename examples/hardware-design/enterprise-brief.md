# W2 企业背景与建模依据

来源标识：`BRIEF-W2@r1`。本文件是作者编写的合成教学材料，供书中第四、六、七、八章共同引用。公司、客户需求、目标、角色和系统安排均为虚构设定，不是客户访谈、已批准的企业战略或真实系统清单。

它补充“为什么开发 W2、由哪些能力和角色支撑”的背景。`inputs.json` 继续独立保存工程计算输入，本文件没有加入 `w2-inputs-r1` 的散列，也不由 `check_design.py` 自动校验。两者发生变更时需要分别评审，不能以计算器通过证明企业模型正确。

## 客户价值与商业模式

澄川设备面向有既有监测点位的仓储运营团队（`SEG-WAREHOUSE`），以出售监测设备获得收入，由渠道与服务合作方参与安装和售后。教学场景提出的客户价值是减少现场维护负担（`VALUE-MAINT`），并沿用已有安装位置。客户是否愿意为此付费、实际更换电池频率和现场维护费用，尚无调查或观测记录。

W2 的单台材料预算为80元；这不是售价、完整制造成本、总拥有成本或利润。研发、试验、认证、渠道和售后成本尚未给出，不能据此推导商业盈利性。目标市场、适用标准和监管要求也待确认，由产品负责人组织核对。

## 目标、举措与产品要求

| ID | 类型 | 说明与当前状态 |
|---|---|---|
| GOAL-MAINT | 企业目标 | 降低既有客户监测点位的维护负担；教学目标草案，目标期间与改善幅度待定 |
| METRIC-VISITS | 指标定义 | 拟按每100个点位每年的电池维护到场次数衡量；覆盖客户、计划维护/故障维护范围及计数规则待确认，没有实际值或预测值 |
| INIT-W2 | 战略举措 | 探索兼容既有安装方式的 W2 升级产品；处于方案探索阶段，无采购或生产授权 |
| W2 | 产品 | 仓储温湿度记录器，当前设计草案为 W2-D0 |
| R-LIFE | 产品需求 | 教学工程目标为连续工作两年，详见 REQ-W2@r1；它只对客户价值提供部分支持 |
| R-MECHANICAL | 产品需求 | 沿用 W1 外壳与安装孔，详见 MECHANICAL-W1@r1；未提供真实 CAD |
| R-BOM | 产品需求 | 单台材料预算不超过80元，详见 REQ-W2@r1；不等同于盈利要求 |

`GOAL-MAINT` 用 `METRIC-VISITS` 衡量，`INIT-W2` 拟推进 `GOAL-MAINT` 并交付产品 `W2`。产品要求还包括 R-SAMPLE、R-UPLOAD 和待明确的 R-MEASUREMENT，完整定义以 `inputs.json` 为准。续航预算通过，不能直接证明维护到场次数减少。

## 能力、价值流与责任

探索、验证并交付可维护的监测产品，需要低功耗设计（`CAP-POWER`）、产品验证（`CAP-VERIFY`）和供应保障（`CAP-SUPPLY`）等能力。它们是为了教学选取的局部能力清单，不是全公司能力目录。

价值流 `VS-UPGRADE` 按“确认客户维护需求—形成升级方案—验证适用性—交付安装—使用与反馈”组织。W2-D0 当前只到形成升级方案阶段；后续阶段没有执行记录。方案评审流程 `PROC-REVIEW` 包括准备草案、专业评审、记录问题与形成决定，支持方案进入下一阶段。

| 角色 | 教学责任安排 | 需要区分的决定 |
|---|---|---|
| 产品负责人 | 确认客户价值、产品要求及其取舍，跟踪 GOAL-MAINT | 需求基线及商业目标的确认 |
| 硬件负责人 | 承担 CAP-POWER，提交功耗、器件和接口方案 | 技术方案评审，不能单独放行量产 |
| 测试负责人 | 承担 CAP-VERIFY，组织验证计划与结果核验 | 判定测试结果是否满足已确认准则 |
| 采购负责人 | 承担 CAP-SUPPLY，核对报价、交期与替代料 | 采购执行仍需独立预算和审批 |

这些角色责任是教学模型中的安排，不是平台授予用户的访问权限或操作令牌。实际人员任职、预算分配及审批记录均未提供。

## 应用、数据与运行反馈

教学目标架构中，产品生命周期管理系统（`APP-PLM`）管理需求基线和设计修订，物料系统（`APP-BOM`）管理物料版本及报价，测试记录系统（`APP-TEST`）管理验证计划和结果，售后工单系统（`APP-SERVICE`）记录维护到场事件。这里给出的是拟采用的职责，并未部署这些应用或接入接口。

配套文件只承担其中的一小部分：`inputs.json` 是工程输入快照，`design.json` 是 W2-D0 草案，`check_design.py` 生成预算与引用检查结果。未来的实测记录必须绑定样机、设计修订、环境与测量条件；维护事件还需关联客户和点位，按照确认后的 METRIC-VISITS 口径汇总，才能检验 GOAL-MAINT。

## 三项建模验收问题

1. 从 R-LIFE 能否查到 W2、INIT-W2、GOAL-MAINT 和客户价值，并分别找到工程要求与企业背景的出处？
2. 更换无线模块后，能否列出低功耗设计、验证和供应保障三方面的核对事项及责任角色？关系用于提出核对范围，不能自动宣布必然影响。
3. 预算检查通过后，能否仍明确报告“实测未完成，维护指标口径和实际值缺失，商业目标尚未验证”？

当前这些问题采用书中表格和文件人工核对。运行计算器可以复算工程预算，但不会执行企业关系遍历或自动验收上述三项问题。
